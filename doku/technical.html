Technical

Die technische Dokumentation beschreibt den Aufbau von KIEZFIT in Version 0.1.0. Das Projekt basiert auf einer klassischen Frontend-Struktur mit HTML, modular aufgebautem CSS und JavaScript für interaktive Funktionen.

Projektstruktur

Die Projektstruktur trennt Dokumentation, Stylesheets, JavaScript, Bilder und zukünftige Seiten voneinander.

HTML-Architektur

index.html

Die Startseite bildet die zentrale öffentliche KIEZFIT-Landingpage. Sie enthält Header, Navigation, Hero, Studio, Leistungen, Kurse, Mitgliedschaften, Kontakt und Footer.

Semantische Struktur

Die Inhalte werden über semantische HTML5-Elemente wie header, main, section, article und footer strukturiert.

Navigation

Die Hauptnavigation verwendet interne Anker auf die einzelnen Bereiche der Landingpage. Der Login-Link verweist auf die vorbereitete login.html.

Zukünftige Seiten

Der Ordner pages/ enthält vorbereitete Seiten für spätere Entwicklungsphasen. Diese Seiten sind Bestandteil der zukünftigen Erweiterung und nicht als vollständige Funktionen von 0.1.0 zu verstehen.

CSS-Architektur

Die Stylesheets sind nach Verantwortungsbereichen getrennt. Dadurch bleiben globale Regeln, Layout, Komponenten, Sections und Responsive Anpassungen voneinander getrennt.

base.css

Globale Reset-Regeln, CSS-Variablen, Farben, Typografie, Spacing, Border-Radii, Border und Transition-Werte.

layout.css

Übergeordnete Layout-Regeln für Header, Sections und Footer.

components.css

Wiederverwendbare UI-Komponenten wie Logo, Navigation, Buttons, Hamburger-Menü und Scroll-Buttons.

sections.css

Spezifische Gestaltung der einzelnen Seitenbereiche, unter anderem Hero, Studio, Leistungen, Kurse, Mitgliedschaften und Kontakt.

responsive.css

Responsive Anpassungen für Tablet, Mobile und besonders kleine Bildschirmgrößen.

CSS-Variablensystem

Zentrale Werte werden in :root definiert und anschließend über CSS-Variablen wiederverwendet. Dadurch werden wiederkehrende Werte zentral steuerbar.

JavaScript

Das JavaScript ist auf die interaktiven Funktionen der Landingpage konzentriert. Es verändert nicht die grundlegende Seitenstruktur, sondern steuert Navigation und Scroll-Verhalten.

Scroll-Navigation

Die aktuelle Section wird anhand der Scrollposition ermittelt. Über die Scroll-Buttons kann zur vorherigen oder nächsten Section navigiert werden.

Smooth Scrolling

Zielbereiche werden über scrollIntoView() mit einer weichen Scrollbewegung angesteuert.

Scroll-Button-Status

Die Buttons werden abhängig davon aktiviert oder deaktiviert, ob sich die Seite am oberen oder unteren Ende befindet.

Hamburger-Menü

Auf mobilen Geräten steuert JavaScript den geöffneten Zustand der Navigation und synchronisiert aria-expanded.

Responsive Architektur

Die responsive Darstellung wird über Media Queries in responsive.css gesteuert.

900px – Tablet

Reduzierte Grid-Spalten, kleinere Navigation, angepasste Überschriften und kompaktere Header-Elemente.

700px – Mobile Navigation

Die horizontale Navigation wird durch ein Hamburger-Menü ersetzt.

600px – Kleine Mobile Geräte

Einspaltige Bereiche, vertikale Buttons und weitere Anpassungen an Typografie und Footer.

350px – Sehr kleine Geräte

Zusätzliche Anpassungen für Karten und Überschriften.

Assets

Die verwendeten Bilder liegen zentral im Ordner assets/images/. Für die produktiv verwendeten Bilder wird WebP eingesetzt.

hero.webp

Hintergrundbild des Hero-Bereichs.

studio.webp

Hintergrundbild des Leistungsbereichs.

kiezfit-preview.webp

Projektvorschau für die Dokumentation beziehungsweise Präsentation des Projekts.

Accessibility

Semantik

Semantische HTML5-Elemente unterstützen eine nachvollziehbare Dokumentstruktur.

ARIA

Das mobile Menü verwendet aria-expanded und aria-controls, um den Zustand der Navigation technisch nachvollziehbar zu machen.

Focus States

Interaktive Elemente besitzen sichtbare Focus-Zustände für die Tastaturbedienung.

Kontrast

Die Farbpalette wurde mit dem Ziel einer klaren visuellen Hierarchie und guter Lesbarkeit aufgebaut.

Deployment

Das Projekt wird über GitHub Pages veröffentlicht. Der aktuelle Stand wird aus dem Git-Repository bereitgestellt. Dadurch steht neben der lokalen Entwicklung eine öffentlich erreichbare Live-Demo zur Verfügung.

Version 0.1.0

Die erste Version konzentriert sich auf eine statische Frontend-Grundlage. Backend, Datenbank, echte Benutzerkonten und serverseitige Funktionen gehören ausdrücklich zu späteren Entwicklungsphasen.
